# 自动记忆与工作日志：实施和验收记录

记录日期：2026-09-28。以下实现/验收结果和“未发布”说明对应该次工作树及执行时点，不能判断当前版本公开状态。现行功能规则见[记忆与工作日志](memory-and-worklog.md)，尚未完成的语义/原生验收见[当前验收与待办](verification-backlog.md)。该次未替换日常应用，也未读出用户服务商密钥来运行模型测试。

## 已实现的行为

- 聊天消息不再常驻“记住这件事”“保存到工作日志”“安排周报”操作；显式工作日志工具及其真实操作回执保留。
- 宿主持久队列处理新回合，依据原生消息确认来源和结束状态。轻聊天及工作台登记到同一队列。内部提取、报告和子会话排除。
- 复用来源回合的 OpenCode 模型，在无工具权限的内部子会话提取结构化信息；不改 OpenCode 内核。完成或失败后清理内部会话，清理失败可恢复。
- 记忆和工作日志独立开关、独立提交与重试。来源幂等、项目路径隔离、更正优先、删除屏障、设置代次检查防止旧任务写回。
- 用户明确自述的工作计划、进展、成果可进入日志；受管 Agent 仅采纳已完成运行中的成功 write/edit 文件操作。助手总结、shell 输出和文件正文不作完成证据。
- 记忆事项通过条目 ID/revision 关联已归档工作；日志变化使关联旧记忆失效。管理页可以查看、修改、删除记忆并查看后台失败、重试，聊天区不增加逐条确认。
- 每轮动态构建记忆上下文；工作台不再读取启动时的记忆正文快照。尚未提取的近期来源可在明确续接请求时提供有界临时上下文。
- 新安装默认开启两项自动功能。已有明确的自动记忆关闭值保留；新增日志自动归档开关独立。当前日常配置原本关闭自动记忆，使用新版时需在设置中开启才能验证自动学习。

## 真实模型验收与当前边界

`scripts/automation-qa/semantic-cases.json` 包含 36 条中英文场景及人工语义预期。`verify-semantics.ts` 可在显式提供测试用服务商环境变量后执行，仅发送合成样例，保存实际输出并检查硬负例/证据；正例仍需按语义人工复核。**本轮未运行真实服务商模型，不能将模拟模型的调用链通过视为语义准确率通过。** 该脚本检验提取提示词本身，宿主的敏感过滤与写库约束由 Rust 测试覆盖。

实际预算和设计起点的差异：

- 按来源回合串行处理，不将多个相邻回合合并成一个模型请求。首次延迟约 2 秒，最多 3 次失败尝试；当前聊天不等待提取结束。
- 每回合最多 48,000 字符，按完整中文句子/段落分成不超过 12,000 字符的块；单段超过预算安全失败，不把截断片段当成完整证据。候选上下文总预算 6,000 字符；每块两分支各最多 5 条。
- 原生来源有界分页最多 8 页、每页 32 条；超出窗口的旧来源显示处理失败，可重试，不静默标为已保存。
- 已确认 Agent 文件进展目前限 write/edit；apply_patch、外部工具和部署结果尚不自动推断为已完成工作。
- 同义更正和同义去重依赖提取模型匹配已有目标 ID/稳定事项键；精确同日记录和同源重放有数据库幂等保护。真实模型的同义判断尚待上述样例验收。
- 仅关联成功归档条目的记忆会随条目修订失效；关联由 workKey 或相同证据确定。未关联的独立目标/偏好保留。
- 普通界面预览和隔离 sidecar 联调已执行；尚未在用户日常应用中进行带真实模型、真实数据库的完整交互验收。
