# 待发送附件栏与图片缩略图

日期：2026-09-27，基于 v0.4.12 的本地修改。

## 实现

- 附件栏移到输入框边框外，位于会话区和输入框之间。浅色主题使用白色不透明底栏，深色主题使用对应的不透明主题底色。
- GIF、PNG、JPEG、WebP 使用已通过暂存检查的原始图片字节生成预览；GIF 不转为静态图。缩略图保留文件名和可访问的移除按钮，悬停可查看大小和状态。
- 普通文件保留文件信息。图片解码失败时回退为文件信息，仍可移除。多附件沿用有高度上限的换行滚动区域。
- 预览仅存在于待发送附件状态；移除、会话重置或发送完成后随状态释放。模型发送仍从暂存源读取原始附件，不依赖缩略图。

## 验证

- `bun run typecheck` 通过。
- 附件栏及附件控制器测试 16 项通过，覆盖 GIF MIME 推断、原始字节、移除、图片解码失败回退及发送后预览清除。
- 聊天发送测试 28 项通过，包含附件区域处于输入框外的结构验证。
- 隔离 macOS 应用构建通过，420×560 原生窗口确认 GIF 缩略图位于白色附件区、图片与文本文件混排、发送后附件区清空。
- 最终构建复核圆形移除按钮；点击移除后附件栏收起。截图 `03-final-gif.jpeg` 和 `04-removed.jpeg` 对应最终样式。
- 原生发送使用本机合成服务；该测试模型仅声明文本输入，OpenCode 将 GIF 替换为不支持图片的提示，文本附件内容正确到达服务。GIF 原始数据进入前端发送请求的检查由控制器测试覆盖，不宣称已通过真实视觉模型理解验收。
- 截图及本机请求记录在 `artifacts/attachment-preview-qa/`（忽略目录）。
