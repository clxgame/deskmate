> 状态：本地实施与 420 × 560 原生窗口验收已完成；完整测试套件的既有失败见第 10 节。
> 实施者：Codex。按用户实施指令完成本地代码和验证。
> 日期：2026-09-27。
> 核对基线：`main`，提交 `3b58987`，版本 `0.4.10`；写计划前工作树干净。开工时重新核对，不覆盖后来出现的用户改动。

## 1. 用户要的结果与本轮范围

将聊天底部合并成一个轻量输入区：左侧是附件和工作文件夹，右侧是当前模型和发送。撤掉常驻的工作文件夹横栏、重复解释和完整路径段落。模型选择对当前会话的后续发送真实生效，普通聊天和文件夹任务行为一致。

已认可的常态结构：

```text
┌─────────────────────────────────────────┐
│ 输入消息…                                │
│                                         │
│ ＋  📁 文件夹 ▾            模型名 ▾   ↑  │
└─────────────────────────────────────────┘

┌─────────────────────────────────────────┐
│ 帮我整理一下这个项目…                     │
│                                         │
│ ＋  📁 deskmate ▾          模型名 ▾   ↑  │
└─────────────────────────────────────────┘
```

交付范围：输入区布局、两个轻量浮层、会话级模型偏好与实际发送贯通、文件夹切换的会话边界、原工作区栏内容重新归位、相关测试和真实窗口验收。

本轮不扩展跨服务商快速切换、推理强度选择、自动模型路由、模型计费面板、多任务并发或新的附件支持能力。服务商/API 配置继续由 AI 设置管理；标题栏和历史列表不重做。

收到实施指令后的默认操作范围是本地实现与验证。版本保持 0.4.10；提交、push、打标签、发布、替换用户日常安装均按该实施会话中的用户授权执行。不要把此前已完成的 0.4.10 发布授权理解成后续版本的发布授权。

## 3. 输入区视觉与基础交互

### 3.1 单一容器

- 输入文字在上，工具行在下；附件托盘仍在同一输入区域内，按需出现。
- 文件夹和模型用无常驻底色的小图标/文字，悬停时出现淡背景；只有发送按钮承担主要强调。
- 去掉当前厚重的输入框外圈，保留细边框及清晰的键盘焦点样式。使用已有主题 token，不新增一套硬编码配色。
- 默认两行输入，保持 `Enter` 发送、`Shift+Enter` 换行；中文、日文、韩文输入法组合期间按 Enter 不得误发。
- `＋` 承接现有附件添加入口；没有第二项已实现功能时直接打开原有文件选择器，不创建无意义的单项菜单。
- 工具行参考：点击区域 28–32px，文字约 11–12px；正文保持现有可读字号。按实际窗口调优，不用缩小全文字体满足布局。
- 420px 宽、无附件/错误/审批、普通字号下，整个输入区以约 88–104px 高为目标。工具条始终一排；文字放大和必要提示可合理增加高度。
- 发送/停止区域固定宽度，文件夹与模型名称使用独立 `min-width: 0` 和上限。长名称省略，完整值可通过菜单和焦点/悬停查看；保留模型版本等必要辨识信息。
- 在 360px 宽压力场景也应能操作。必要时未选目录入口可缩为带无障碍名称的图标；已选目录和当前模型仍能辨认，不挤掉发送按钮。

### 3.2 两个浮层共用的行为

- 点击入口后向上展开，位置受实际可视区约束；菜单最多占可用空间，长列表在内部滚动，不能被输入区或窗口 `overflow` 裁切。
- 同时只打开一个浮层。点击外部、选择成功、Escape 均关闭；关闭后焦点回到触发入口，正常选择完成后可回到输入框。
- 支持 Tab、方向键、Enter；菜单里的 Enter 仅执行菜单动作，不能冒泡触发发送。Escape 优先关闭浮层，不能同时关闭聊天窗口。
- 采用与菜单/可搜索列表匹配的 ARIA 语义；选中项、加载、错误均可访问。不能靠 tooltip 承载唯一的操作含义。
- 复用已有图标组件和依赖。不要为两个简单浮层引入大型 UI 库。

## 4. 文件夹入口与会话切换

### 4.1 文案与菜单

- 未选择时显示 `文件夹 ▾`；选中时显示 `文件夹图标 + 末级目录名 ▾`。
- 完整路径在菜单中查看，重名目录增加最短必要的父目录。显示名不作为路径或历史身份。
- 菜单包含：最近使用的 3–5 个明确工作目录、`选择其他文件夹…`、选中时的 `退出文件夹工作`。
- 首次没有最近目录时直接给选择动作，不展示空列表或教学段落。选择新位置调用已有系统目录选择器。
- 最近目录只来源于用户明确选取/使用过的文件夹任务；去重使用规范化路径。排除内置轻聊天 workspace，不把目录发现列表直接当成 MRU，更不能扫描全盘。
- 目录不可用时保留可辨认名称并给出原因和重新选择入口；失败不替换当前有效目录，不丢草稿。取消系统选择器不改变状态。

### 4.2 切换规则

1. 尚未开始的任务可更换待用目录，保留草稿和当前模型偏好。
2. 已经有内容的会话选择另一个工作目录时，开启新的文件夹任务上下文。旧会话留在历史里，原目录和消息不变；不要把旧消息自动作为新任务重放。
3. 退出已有文件夹任务时，回到新的普通聊天上下文。保留尚未发送的文字和模型选择；旧任务仍可从历史打开。
4. 上述由文件夹入口发起的切换，是用户携带当前草稿继续工作，模型偏好随草稿保留；这与明确点击 `新会话` 不同，后者重置为跟随默认模型且不自动选工作目录。
5. 明确建立目标会话后才提交切换；失败/取消时回到原视图。不能先清空消息和附件再创建目标。
6. 运行中、启动中、停止未确认、历史加载中或运行状态未知时，禁止更换实际执行目录。入口提供简短原因，保留正确的当前路径。
7. 恢复历史时以宿主返回的目录为准，不能残留上一个页面的 `agent.workspace`。目录缺失的历史可查看，不能绕过现有只读限制继续执行。

### 4.3 附件冲突

- 已有附件时选择文件夹，先就近说明 `文件夹任务暂不支持附件`，提供 `保留附件继续聊天` 和 `移除附件并进入文件夹工作`；只有用户明确选择后者才移除附件。
- 冲突处理保留文字草稿。选择目录取消、失败或并发状态改变时，不能丢附件。
- 进入文件夹任务后，附件入口保持可理解的不可用状态和原因。拖入、粘贴文件也受同一限制，不能只禁用按钮。
- 继续复用当前附件的准备、取消、清理和会话归属机制；不要增加文件任务附件能力。

## 5. 模型选择：UI、会话偏好与真实执行

### 5.1 展示与菜单

- 主工具行只显示实际有效模型的短名称和下拉标记，省掉 `模型：`、供应商徽标、能力标签及计费信息。
- 跟随默认时，只要能可靠解析，仍显示实际模型名；菜单中的 `跟随默认 · 模型名` 带选中标记。手动选择与跟随默认必须是不同状态，即使两者当前解析成相同模型。
- 菜单列出**当前活动服务商、当前验证绑定下可用的模型**。不列所有服务商，不依赖显示名称判断同一个模型。
- 首版将当前项置于容易看到的位置，其余稳定排序；数量较多时提供搜索。不要额外建设常用模型管理页。
- 底部 `管理模型…` 打开 AI 设置并定位模型相关区域，保留聊天草稿。若当前设置入口不支持定位，补最小的导航参数/事件并兼容现有无参数调用。
- 无配置、未验证、列表加载失败、当前模型失效要区分：给出选择/重试/前往设置等对应动作。不得伪造模型名单，也不得静默使用第一个模型。
- 一次列表请求失败不等于模型已被移除：保留已选记录，显示加载失败/重试。是否可发送由可靠的宿主校验结果决定，不能因暂时取不到列表就清掉覆盖偏好。

### 5.2 作用范围和持久化

模型偏好的概念结构如下，名称可按仓库习惯调整：

```ts
type ConversationModelSelection =
  | { mode: "inherit" }
  | {
      mode: "override";
      configuredProviderId: string;
      sidecarId: string;
      modelId: string;
    };
```

- `configuredProviderId` 是设置中的服务商条目 ID；`sidecarId` 才是发送给 OpenCode 的 provider ID。两者不能混用。
- 模型选择只影响当前会话**下一次及后续发送**，不改全局设置、不影响别的会话、工作台或定时任务。
- `新会话` 使用 `inherit`。恢复已有会话时恢复该会话的偏好；关闭窗口、重启应用、刷新历史后仍保持。旧记录缺少字段时默认为 `inherit`，不从旧消息猜测用户选择。
- 以完整 catalog key 持久化；禁止用裸 `sessionId`、标题或目录显示名作为唯一键。两个项目存在同名 session ID 时也必须隔离。
- 首选扩展现有宿主 catalog 的可选 composer/model 元数据，或在同一 catalog 数据库中增加按完整 key 关联的偏好表；施工时选定一种，不维护双份权威状态。采用向后兼容的读取/迁移并同步更新历史契约文档。
- 目录发现、同步、重命名、置顶、归档均应保留偏好；单纯改模型不修改消息时间、不让历史排序跳动。删除会话时按同一数据生命周期处理偏好。
- 检查 legacy→native 合并和现有条目重新发现的路径；只有完整身份匹配时才保留/迁移偏好，不能从裸 ID 相同的另一目录借用值。
- 未获得真实会话身份的草稿先持有待用偏好；Agent 首次启动创建 native 会话后，将偏好绑定到返回的完整身份。绑定失败要可见且可恢复，不误写到此前正在查看的聊天记录。
- `inherit` 在下一次发送时重新解析当时的默认模型；`override` 保持明确选择。活动服务商变化、条目删除、验证失效或模型下架后，失效覆盖显示 `重新选择`，阻止错误发送，用户可改为跟随默认。不能偷偷退回其他模型。
- 不把 API key、端点凭据或密钥指纹写入会话元数据和日志。

### 5.3 同一选择贯通两条发送链路

1. 建立共享的模型选择校验/解析规则：活动服务商匹配、条目和 runtime provider ID 对应、已验证模型目录有效、模型确实存在。后端复用 `load_verified_model_catalog_for_provider` 等现有绑定校验，不能只相信前端传来的字符串。
2. 普通聊天发送给 `promptAsync` 的 `{ providerID, modelID }` 来自当前会话的有效选择。必要时增加最小的宿主解析接口，返回可发送的模型对；UI 显示和实际请求使用同一解析结果。
3. 文件夹任务扩展 `startAgentRun → useAgentRun.start → agent_run_start` 的契约，传递待用会话选择或读取已保存的会话选择。宿主在验证身份和可发送能力后解析模型，写入本次 `StartSettings` 快照；`lifecycle_client`、首次请求和后续工具回合都用该快照。
4. 后端 continuation 继续固定历史目录；客户端携带的模型选择不能成为覆盖目录、绕过只读或修改其他会话的入口。新增命令沿用聊天窗口鉴权和现有运行互斥规则。
   Agent 历史能否续作沿用 `catalog_start_target` 等既有规则；不要机械套用普通聊天的 `capabilities.send`，把合法的 Agent 续作也全部拦住。
5. 发送被接受时锁定本轮模型。普通回复、Agent 启动/执行/停止期间均锁定选择；后台设置变化不让运行中的标签跳成另一模型，也不改变本轮实际模型。结束后再重新校验下一次发送。
6. 点击发送后若还有附件预处理、历史校验等异步步骤，捕获会话身份和本轮选择，阻止过期回调把 A 会话的选择/内容提交到 B 会话。模型列表和偏好读取同样需要请求代次控制。
7. `inherit` 的全局默认为空时，先核实 pinned OpenCode 的默认模型是否有可靠的解析来源；能可靠解析则显示真实值并固定用于发送，不能则显示 `选择模型` 并要求明确选择。不要假设列表首项就是默认。
8. 定时任务继续使用原有设置快照。新字段可选、旧调用方兼容，但聊天请求的显式无效覆盖必须报错，不能用“可选参数”掩盖失效。

这是端到端功能，不接受“工具行显示了模型名，但 Agent 仍调用全局默认”的交付。

## 6. 任务反馈、审批与停止的归位

- `WorkspaceTask` 可拆分或退役，但保留其实际能力：运行进度、错误、审批、结果文件、定位文件和历史不可用原因。
- 进度、完成/失败状态和结果随对应任务在消息区域显示，以真实 run ID 和会话复合身份归属；普通空白聊天不显示上一次任务的残留结果。
- 原先常驻的 `最近任务` 不继续占底栏；历史与对应任务记录承担该信息。
- 待审批时在输入区上方显示**临时审批区域**，让用户即使滚动到旧消息也能发现；审批结束即移除。复用 `ToolApprovalCards` 和原有 once/always/reject 行为，保留命令、目录、记住规则的作用范围、提交失败重试等信息。
- 同一请求不能在消息区和底部生成两个可操作副本。禁止为了变轻而默认允许、折叠隐藏必要审批或删掉拒绝入口。
- 普通聊天与 Agent 审批的请求来源、reply API 和所属运行不同。展示可以复用，处理回调必须按来源绑定，不能因合并组件而混用。
- 统一右侧发送/停止位置：普通回复停止调用原来的普通聊天取消链路，文件夹任务停止调用 `agent.stop`；停止未确认保持锁定并显示原因，不能假装空闲。
- 现有单任务约束保持。运行中的任务不属于当前打开的历史时，显示简短的真实任务状态和 `返回任务` 入口，审批/停止指向该任务，不能附着到当前另一条会话。
- 只读、归档、legacy、工作台占用和未知状态沿用原可发送能力；新模型/目录入口不能重新放开这些记录的发送。

| 工作包 | 主要内容 | 建议涉及位置 |
| --- | --- | --- |
| A：状态与契约 | 明确 draft/current/running 身份、模型选择与解析类型、目录转换；补纯规则测试 | `src/chat/` 的新 controller/model 模块，`src/lib/unifiedHistory.ts`、`src/lib/agent.ts` |
| B：宿主偏好和模型解析 | 持久化兼容、绑定校验、Agent 请求贯通、运行快照、旧调用兼容 | `src-tauri/src/history/`、`settings.rs` 或独立解析模块、`agent/run_commands.rs`、`start_context.rs`、`lib.rs` 命令注册 |
| C：输入区与浮层 | 统一 composer、附件入口、目录菜单、模型菜单、键盘焦点与窄窗 | 建议 `ChatComposer.tsx`、`WorkspacePicker.tsx`、`ModelPicker.tsx`、共享小型 popover、`chat.css` 或独立 composer 样式 |
| D：会话和任务接线 | 两条真实发送链路、历史恢复、目录换会话、停止、审批和结果归位 | `ChatApp.tsx`、`useAgentRun.ts`、`useAgentHistoryView.ts`、`WorkspaceTask.tsx`、`ToolApprovalCards.tsx`、附件相关 hooks |
| E：文案与验收 | 四种语言、主题、完整交互测试、窗口截图、契约与交付记录 | `src/lib/i18n.ts`、对应测试、历史契约、本文执行结果附录 |

推荐顺序：先完成 A/B 并验证真实模型请求，再做 C/D；最后做 E。不要先画一个不可工作的模型下拉，留下“后续接后端”。

`src/settings/aiProviderModel.ts` 中可复用的纯规则可提取至 `src/lib/`；聊天组件不应为取得列表而挂载整个设置页控制器，也不能在选择模型时调用保存全局 settings。

## 8. 必须覆盖的验收矩阵

| 场景 | 通过条件 |
| --- | --- |
| 空白聊天 | 单一输入容器和一排工具；没有常驻工作文件夹栏、完整路径或解释段落 |
| 420×560、720×760、360px 压力宽度 | 名称截断合理，菜单不出界，发送/停止始终可点；无多出的一排工具 |
| 文件夹选择成功/取消/失败 | 状态正确，草稿保留，取消和失败不改原会话；最近目录去重且来源明确 |
| 有内容的聊天切换目录/退出任务 | 旧历史身份不变，新任务采用新目录；未发送文字和模型偏好按约定保留 |
| 附件后选文件夹、粘贴/拖入附件 | 冲突在操作时可见，无静默丢附件；各入口规则一致 |
| A 会话选模型 B、切到会话 C | 只改变 A 的后续请求；C、全局默认和定时任务不变 |
| 关闭窗口、重启、历史刷新 | 会话覆盖恢复；旧记录无偏好时使用 inherit；偏好不影响历史排序 |
| 两目录中同名 native session ID | 模型偏好、进度、审批和结果不串会话 |
| 普通聊天选非默认模型 | 验证真实 `promptAsync` 请求模型对，不只断言 UI 文字 |
| 首次 Agent 任务与历史续作选非默认模型 | 宿主实际请求使用选择的模型；工具后续回合仍是同一快照；新会话正确绑定偏好 |
| 运行时设置变更 | 本轮模型与显示不漂移；结束后重新校验；下一次 inherit 按新默认解析 |
| 非法/失效/跨服务商模型、验证绑定改变 | UI 和宿主均拒绝错误选择，不悄悄改用其他模型；可重试或重新选择 |
| 模型和历史请求 A/B 乱序返回 | A 的旧结果不能覆盖 B 当前状态；关闭菜单和切会话后不误写偏好 |
| 普通回复停止 / Agent 停止 | 分别命中正确取消链路；失败和未确认不误解锁、不会自动重发 |
| 审批与滚动 | 必要审批可见、操作单一、规则作用范围明确；无自动授权或请求丢失 |
| 历史只读、归档、缺目录、工作台占用 | 保持已有限制，新工具条不能绕过；错误不变成“空目录普通聊天” |
| 键盘与输入法 | Tab/方向键/Enter/Escape 正常，浮层不误发消息，IME 确认不触发发送 |
| 四种语言和现有主题 | zh-CN/en-US/ja-JP/ko-KR 无漏译、挤压或不可辨认的禁用状态 |
