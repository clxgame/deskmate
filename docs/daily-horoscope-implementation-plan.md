## 1. 本次范围与产品决策

| 项目 | 首版决定 |
| --- | --- |
| 入口 | 与定时任务、番茄钟、工作日志并列的第四个小组件 |
| 内容 | 今日最旺、12 星座详情、综合/爱情/事业/财运/活力、宜忌、幸运色/数字、Yume 点评 |
| 我的星座 | 可选，可清除；只保存星座 ID，不收集生日等信息 |
| 默认详情 | 每次进入默认展示今日最旺；设置个人星座后增加「我的星运」快捷入口 |
| 日期 | 设备当地日历日期，00:00 换日，支持睡眠恢复和系统日期调整 |
| 数据来源 | 日期 + 固定生成版本 + 本地内容池，无网络和模型调用 |
| 展示 | 指数显示 1–5 颗整数星；内部保留加权精度用于排名 |
| 并列 | 展示星级可以相同；内部综合分严格只有一个最高者 |
| 连续最旺 | 建议采用下述确定性规则，硬性限制最多连续两天 |
| 宜/忌 | 纳入首版；修正原 prompt 将其同时列为未来功能的冲突 |
| 桌宠提示 | 本轮不增加桌宠旁文字、气泡、悬浮卡片或新窗口；后续可单独设计 |

不做星盘、出生信息、账户、同步、服务器、新数据库、AI 生成、第三方 API、天气/BGM、通用 DailyEngine。没有刷新抽签按钮，不允许同一天重抽。

本方案中的日期分组、分数档位、幸运数字范围和文案数量是为接手施工给出的具体设计选择，并非声称原 prompt 已指定这些细节。可在不改变产品范围和不变量的前提下简化实现。

交互约定：

1. 点击第四个入口时在原内容区显示；不新增侧边栏分类、模态弹窗或独立窗口。
2. 始终保留「今日最旺」快捷入口；选择其他星座不会改变当天榜首。
3. 「我的星座」使用现有样式的原生 select，默认未设置。修改偏好只保存选择，不重新生成运势；「我的星运」点击后显示该星座详情。
4. 详情选择用 `ZodiacSign | null` 即可：`null` 表示跟随今日最旺，具体 ID 表示正在浏览该星座。午夜刷新时前者跟随新榜首，后者保持所选星座并更新内容。
5. 离开小组件可卸载星运视图，回来重新读取当天数据并默认展示最旺；只持久化「我的星座」，不持久化浏览位置。
6. 全部星座按白羊到双鱼的固定顺序展示，不做排名榜排序；用标记突出当天最旺。现有设置窗口为 720×520 / 1040×760，正文允许纵向滚动；紧凑布局支持换行，窄窗口退为较少列，不能固定卡片高度导致内容截断或横向溢出。浏览其他星座不会自动修改「我的星座」。
7. 接入现有四种主题；不添加宇宙背景、大渐变、自动播放动画或新字体。入口图标在 AppIcon 中增加 `horoscope` 语义别名，可复用已引入的 Sparkle。
8. 星座符号可使用文本符号，名称必须同时存在。星级提供如「事业，4 / 5」的本地化可访问名称，装饰星星对读屏隐藏。
9. 所有选择都是原生按钮/select，有清晰 focus-visible 和选中状态；不要给普通按钮套不完整的 ARIA tabs 行为。更新不抢焦点。

## 4. 纯函数数据层

建议放在 `src/lib/horoscope/`，不依赖 React、Tauri、设置、网络或当前时间。

建议接口：

```ts
generateDailyHoroscope(dateKey: string): DailyHoroscope
localDateKey(now: Date): string
nextLocalMidnight(now: Date): Date
```

`generateDailyHoroscope` 的算法版本用明确常量，例如 `HOROSCOPE_GENERATOR_VERSION = 1`。调用者不能传入用户姓名、语言、个人星座等影响 seed 的参数。

模型在原 prompt 上作必要调整：

- `ZodiacSign` 为固定十二种英文 ID；固定顺序与符号放 `zodiac.ts`。
- 每个结果包含四维整数星级、`overallUnits`（整数加权分）以及可派生的综合展示星级。
- 幸运色、宜、忌、点评使用稳定内容 ID，数字直接存数值；本地化在展示层完成，不把中文句子作为逻辑 key。
- `DailyHoroscope` 包含 `date`、`generatorVersion`、唯一 `topSign`、十二条 `fortunes`。
- 不保存完整运势、生成历史、上次访问日期或连冠记录；重复计算成本足够小。

### 4.1 日期、随机数与版本

- `localDateKey` 用 `getFullYear/getMonth/getDate` 拼当地 `YYYY-MM-DD`。不能用 `toISOString().slice(0, 10)` 获取当地日期。
- PRNG 可用小型固定 32 位 hash + Mulberry32，显式处理无符号位运算。禁止 `Math.random()`、随机排序 comparator 和浮点 hash。
- seed 使用有分隔符的命名空间，例如 `yume-horoscope|v1|2026-09-30|gemini|message`。
- 最旺、分数、幸运色、数字、宜忌、点评各自派生 seed，避免增加一句文案意外改变所有星座的分数。
- 升级 PRNG、分数组合、分配规则或内容选择规则/ID 池时递增生成版本。不得使用应用版本号作为 seed，以免无关升级改变当日内容。
- 切换语言只翻译同一组 ID；同一当地日期、同一生成版本的分数、榜首、内容 ID 在不同用户/设备上相同。

### 4.2 最多连续两天最旺

采用三天分组，避免历史持久化和递归回算：

1. 将明确的年月日按 UTC 日历转换为整数日序号。UTC 只用于日历编号，不用于确定用户今天是哪一天。
2. `block = floor(dayOrdinal / 3)`；`offset` 使用非负模运算，取 0、1、2。
3. 用 `version | top | block` 为 seed，Fisher–Yates 洗牌十二星座。
4. 取前 3 项分别作为该组三天的最旺候选。

同组三天候选互异；相邻两组交界可以重复一次，因此连续上限为两天。每组重新洗牌全部星座，没有固定十二天轮庄，也不承诺每个星座在短期内均匀夺冠。

这是一种先确定候选、再生成满足约束的趣味分数的方案。它有「同组三天不会连庄」的轻微规律，接受这一取舍以保持实现简单。

### 4.3 分数与唯一排名

四维为 1–5 整数，加权时只使用整数：

```text
overallUnits = career * 3 + wealth * 2 + love * 2 + energy * 3
overall      = overallUnits / 10
displayStars = round(overall)
```

使用少量经过校验的四维组合常量，按 seed 选取：

| 组合池 | overallUnits 范围 | 当天分配 |
| --- | --- | --- |
| 最旺 | 45–48 | 1 个候选 |
| 较低 | 18–29 | 2 个星座 |
| 中等 | 30–38 | 6 个星座 |
| 较高 | 39–44 | 3 个星座 |

- 每个组合至少两个维度不同，组合池覆盖不同强项，避免事业/爱情等维度始终占优。
- 把剩余十一星座按日期 seed 洗牌后分档，再按星座独立 seed 选组合；不要给某星座固定高低档。
- 建议各池准备约 6–8 个不同组合即可；以可读常量表达，不做规则 DSL、无限重抽或递归优化。若使用排列压缩常量，应重新按权重归档，不能假设交换维度后综合分不变。
- 最后必须从实际生成的十二份结果求最高分，得到 `topSign`，并保证它等于候选且严格高于其他十一项。不能只修改榜首标签或额外加一个不体现在分数里的排名补丁。
- 展示星级允许并列，最旺按内部加权分区分；无需在 UI 额外显示百分制或小数。

## 5. 文案与国际化

内容池先按语义组织，再逐条翻译，不能每种语言分别随机抽取。

- 「宜」2 条，「忌」1 条，点评 1 句，幸运数字 1–9，幸运色约 8–12 种。
- 宜优先匹配高分维度；忌匹配低分维度；点评匹配主导状态。可将 4–5 星视为高、1–2 星视为低、3 星视为中；没有对应高/低项时使用适用于所有分数的温和通用内容，不伪造低分解释。三类文案都必须有足够的兜底候选。同一活动不可同时出现在宜和忌中，抽取不得重复。
- 只有满足适用条件的文案才进入候选池。例如「购物车先别急着结算」对应较低财运；不要在财运五星时无条件抽出。
- 每个维度的高/低状态准备约 3–4 条适用点评，另有少量中性兜底；每维准备至少 3 条宜、3 条忌。避免十二星座全复用同一两句，首版也无需数百条文案。
- 文案简短、温和、不夸大预测；固定使用 Yume 署名，不接入桌宠 persona 或聊天模型生成。
- 标签、星座名、幸运色名、宜忌和点评覆盖现有四种语言。翻译表按稳定 ID 校验完整性，未知语言与主 `dict` 一致回退中文。
- 可采用 `content.ts` 放语义池、适用条件与内容翻译，`horoscopeLabels.ts` 放 UI 标签和星座名称；不要求改造现有大 i18n 文件。
- 内容 ID 选择不受语言或主题影响；新增译文不得消耗评分用的 PRNG。

## 6. 设置保存与兼容

只增加一个可空字段即可，暂不创建泛化偏好对象：

```text
TypeScript: horoscopeSign?: ZodiacSign | null
Rust / JSON: horoscope_sign / horoscopeSign，默认 null
```

- 前端控件走 `patch("horoscopeSign", value)`；清除时保存 `null`。
- Rust 侧用小型校验/反序列化辅助函数识别十二个 ID。缺省、null、未知 ID 或错误字段类型都只将该字段恢复为未设置，不能让整个 Settings 加载失败而丢掉已有配置。
- 前端同样校验读到的 ID，兼容旧 fixture 和未知值；不要把未经检查的字符串强转为 ZodiacSign。
- 不新增 horoscope IPC、SQLite 表、localStorage 副本或后台写入。
- 保存只是普通设置变更；不得接入番茄钟状态、工作日志调度、AI 记忆或 provider 配置逻辑。
- 保留 `legacySettingsFixture()` 缺少新字段的旧配置语义，新增场景通过 overrides 提供偏好，不必批量改写所有旧 fixture。

## 7. 日期刷新与组件生命周期

在 `useDailyHoroscope.ts` 中维护当天 key，调用纯函数生成结果；与 UI 选择状态分开。

1. 首次挂载立即从当前系统时间读取当地日期。
2. 用当地日期构造下一天 00:00 的单次 timeout。每次执行重新读取实际时间并安排下一次，不能固定加 24 小时，避免夏令时偏差。
3. `focus`、`visibilitychange`（恢复可见时）、`pageshow` 时立即校验日期并重新安排 timeout。
4. 可见期间增加 60 秒一次的低频校验，处理系统日期/时区手动变化。无日期变化时不重新生成、不写设置、不触发额外请求。
5. 日期回拨同样切回对应日的数据；不是只接受递增日期。睡眠跨多天直接读取当前日，不补算每个错过的日期。
6. 隐藏时不做无意义刷新；返回可见/重新挂载必须立即校验。所有定时器和监听器在卸载时清理。
7. 普通持续运行时在当地午夜更新；恢复焦点/可见后立即更新；无事件的系统时间变更在恢复调度后最多约 60 秒校验到。浏览器/系统暂停期间不声称能够执行计时器。
8. 不复用工作日志的工作日边界，星运固定按当地 00:00；不创建原生后台 ticker。

测试使用可控时钟或隔离的 fake timers，参考既有测试方式，不建设全局 Clock 服务。确保恢复 `Date`、timer 和 visibility 等测试环境修改。

## 9. 施工顺序与检查点

1. **核对基线**：读取 AGENTS.md、本方案、目标文件及当前 git diff；如仓库已变化，保留用户修改并调整接入点。
2. **纯数据层**：完成日期、ID、PRNG、生成器及分数组合；先通过确定性、范围、排名和连冠约束测试。
3. **内容和翻译**：补足四语言文案，验证各类分数都能匹配文案、宜忌不冲突，语言切换不改数值。
4. **偏好链路**：同步 TS/Rust 字段，通过旧配置与坏字段兼容测试；复用现有保存。
5. **刷新 hook**：覆盖午夜、跨日恢复、回拨、卸载清理，再接入 UI。
6. **小组件接入**：实现详情、十二星座选择、个人快捷入口；检查四主题、紧凑窗口、键盘操作和既有组件状态。
7. **集成与交付**：完成下述验证、修复自身问题、更新简要文档，给出实际测试结果和剩余平台限制。

接手后按方案继续施工，不重复做一次长篇规划；遇到真正改变产品范围的冲突再向用户说明。各阶段无须重复请求批准。任务本身不包含版本号变更、提交、push、打包、公证或发布。

## 10. 验证与验收

### 自动测试

- 同日期同版本深度相等；重建实例、改变调用顺序也不变。保留少量明确日期的期望样例，防止 seed 或算法意外漂移。
- 始终十二条且 ID 唯一，四维 1–5 整数，加权公式正确，最旺严格最高且等于候选。
- 在连续约一年样本内校验范围、档位、高低项和连冠最多两天；跨三天块、月末、年末、闰日均覆盖。不要断言两个不同日期每个字段都必须不同，也不要用 `date` 不同冒充内容变化。
- 不同代表日期的实际分数/内容有变化；不强求随机样本的精确公平频率。
- 语言、主题、个人选择不影响当天原始数据；每种语言覆盖所有可选内容 ID 和十二个星座，缺失翻译不能在 UI 显示 undefined。
- 宜忌不重复/冲突，点评满足分数条件，幸运数字/颜色来自指定范围。
- 当地日期不会被 UTC 偏移错一天，下一午夜支持 23/25 小时的夏令时日；相关时区用隔离测试进程或可控日期样例，避免全局 TZ 污染其他测试。
- 持续打开跨午夜、隐藏后恢复、睡眠跨多天、系统日期前调/回拨、无事件低频校验、卸载/重挂均能得到正确日数据，无重复监听和定时器泄漏。
- 无偏好默认最旺、设置/清除偏好、点击全部十二星座、返回最旺、日期切换保留手动查看的星座。
- Rust：旧 JSON 缺省正常；null/未知 ID/错误类型只重置新字段；有效 ID 序列化往返；无关字段保持。
- 集成：新增入口可达，设置保存 payload 含新字段，重开读取后保留；定时任务草稿、工作日志 Activity 和番茄钟行为不回归。
- 星运数据生成/浏览本身没有网络、LLM 或新 IPC。不要把设置页已有更新检查等无关流量误判为星运请求。

```sh

```

原生 Settings 有修改时，运行覆盖其模块的 Rust 测试，例如：

```sh
DEVELOPER_DIR=/Library/Developer/CommandLineTools cargo test --locked --manifest-path src-tauri/Cargo.toml --lib settings::
```
