# 空白会话历史规则

2026-09-27，基于 v0.4.11；版本未变更。

## 产品行为

- 仅打开聊天、新建会话、选择模型/文件夹或编辑草稿，不产生可见历史记录，也不增加历史数量。
- 原生会话存在任意消息即可保留：用户发出一条尚未得到回复的消息、只有附件的消息、工具消息都算有效记录。
- 本地固定回复、旧版文本记录、Agent 任务记录均保留。
- 空白状态不通过标题或“暂无可预览内容”判断。访问失败、格式异常、范围不匹配、超限响应都不能证明会话为空。
- 历史刷新时检查原有未分类条目，确认空白后从列表、计数、搜索及归档结果排除；之后发送首条消息即可重新出现。

## 实现边界

目录新增兼容旧数据的可选 `hasRecords` 状态：未验证、有记录、确认空白。消息存在性查询按完整目录/会话身份验证，读取原生消息端点 `limit=1`，不使用文本预览结果。过滤发生在搜索、排序和分页计数之前。

聊天仍需要原生会话身份保存当前模型选择、发送请求和接续工作台，因此保留其内部上下文元数据；不对仍可能发送消息的原生上下文发出删除请求，不建立删除标记。这里清理的是可见历史，不是删除底层原生会话。草稿阶段的身份继续可用，不影响首次发送。

旧版本元数据缺少 `hasRecords` 时视为未验证，待成功刷新后分类。已确认有记录的会话不会因之后离线或预览为空而消失；空白会话的更新时间变化会使其重新待验证。目录导入会用本地消息及 Agent 记录补充保留证据。

## 原生验收

隔离 macOS QA app（420×560）构建通过，保留独立数据目录及本机合成模型服务：

- 原有 3 个目录条目中，1 个旧空线程被识别并排除；原附件会话和 Agent 任务保留，历史显示 2 段。
- 本次打开聊天及再点“新会话”产生的 2 个空上下文不增加历史数量，仍显示 2 段。
- 首次发送 `EMPTY_HISTORY_FIRST_MESSAGE_20260927`，让合成模型延迟 12 秒回复：回复尚未完成时，历史已经显示用户消息，数量变为 3 段。
- 完成后目录中 2 个空上下文、3 个有记录会话，0 个删除标记。截图及计数证据保存在 `artifacts/empty-history-qa/`。
