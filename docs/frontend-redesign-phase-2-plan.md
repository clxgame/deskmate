# YUME 设置界面第二轮改进：规划与施工方案

> 状态：P0 已完成，0.4.6 macOS 手动安装验收包已签名、公证并校验；原生窗口交互仍待实机验收。P1 材质统一与 P2 原生效果仍作为后续独立阶段。
> 基线：YUME 0.4.5，`codex/frontend-redesign`，提交 `82c128e`。
> 主要验收平台：macOS Apple Silicon；默认设置窗口：720 × 520。

## 0. 评审后的施工决定

- **确认事实**：实际导航有八项；现有导航实现按按钮列表工作，七项模拟测试已经落后。将测试接到真实导航组件，保留现有快捷键映射。
- **已复现并修复**：角色包卸载使用 ARIA 确认框，原快捷键守卫只识别原生 dialog。真实确认框测试先失败再通过；覆盖 Ctrl/Command 导航、弹窗取消后的恢复与隐藏弹窗。
- **本轮交互边界**：保留点击角色包即切换首个角色的行为，增加清楚的操作说明。角色选择、包库与安装操作仍由同一个组件协调；通过内容插槽调整控制区位置，不复制状态。
- **布局原则**：优先展示当前角色、大小和显隐；导入入口跟随包库。首屏完整展示通用设置是默认尺寸下的验收目标，错误信息、较大字体和动态内容允许自然滚动。
- **文本原则**：四款固定主题完整显示，可自然换行；不缩小正文或截断名称来强行达成首屏目标。
- **实施拆分**：P0 只改结构、尺寸与必要的交互修复；透明度、阴影和模糊维持基线。关于页保留简介、作者及联系入口。
- **验证原则**：测试覆盖真实组件和行为；分别记录事实、复现结果与设计体验，不把测试数量当作完整体验证明。

## 1. 改造目标

保留上一轮已经形成的四款主题、Bento 卡片和控件质感，提升设置界面的空间利用率、阅读效率与页面一致性。

本轮优先级：

1. **常用设置在首屏可见。** 先解决卡片过高、角色选择入口靠后的问题。
2. **每条信息只表达一次。** 删除重复标题、分类徽标和没有实际帮助的说明。
3. **统一各页面的视觉规则。** 复杂页面保留适合自身内容的布局。
4. **独立评估原生毛玻璃。** 在布局稳定后验证 macOS 原生效果，单独交付。

本轮完成后，用户应能更快找到主题、角色、大小和显示开关，同时保留清晰的分组和键盘操作提示。

## 2. 当前问题与处理决定

| 当前问题 | 使用上的影响 | 处理决定 | 优先级 |
| --- | --- | --- | --- |
| 默认窗口中卡片内外留白偏多 | 通用页的完整主题选择需要滚动 | 压缩面板、卡片和行间距，移除重复内容 | P0 |
| 「桌宠」标题旁再次显示「桌宠」徽标 | 视觉元素增加，信息量没有增加 | 移除纯分类徽标，保留有意义的状态提示 | P0 |
| 昵称单独占据一张大卡片 | 角色包和角色选择被推到下方 | 昵称改为紧凑表单行，调整桌宠页顺序 | P0 |
| 主题卡片内再次出现同名行标签 | 重复占用横向空间 | 标题下直接展示主题网格，保留无障碍名称 | P0 |
| AI、权限、小组件等页面尚未统一整理 | 页面之间的密度和层级不一致 | 按内容类型统一标题、分隔、控件与提示样式 | P1 |
| 多层透明面与阴影叠加 | 深色主题容易显灰，层级不够明确 | 收敛材质层数和阴影强度 | P1 |
| 网页模糊未接入原生桌面背景效果 | 实际效果与“系统毛玻璃”的预期有差距 | 将原生 Vibrancy 作为独立验证项 | P2 |

## 3. 施工边界

- 沿用 React、TypeScript、Vite 和 Tauri，以及现有设置读写接口。
- 第一、二阶段主要修改设置组件及样式；保持设置字段、自动保存行为和已有功能。
- 四款主题与中、英、日、韩四种语言继续支持。
- 继续使用真实入口 `src/settings/main.tsx` 和 `settings.html`。
- 桌宠渲染、聊天业务、AI 请求、更新流程不属于本轮功能改造范围。
- `src/theme.css` 由设置、聊天和桌宠共享；调整其中的变量时，需要检查另外两个窗口。
- 原生材质如需调整 Tauri 配置或平台代码，应单独提交，便于验证和回退。

## 4. 第一阶段：压缩布局与清理信息（P0）

### 4.1 建立统一的紧凑尺寸

以下尺寸作为第一版施工起点，最终依据真实窗口和多语言截图调整。

| 项目 | 当前值或表现 | 首轮调整目标 |
| --- | --- | --- |
| 内容面板内边距 | 上下 20px、左右 24px | 上下 16px、左右 20px |
| 卡片内边距 | 上下 16px、左右 20px | 上下 12px、左右 16px |
| 卡片之间距离 | 16px | 12px |
| 表单行上下内边距 | 各 12px | 各 8px，结合控件高度微调 |
| 卡片标题与内容间距 | 12px | 8px |
| 正文与表单标签 | 13px | 保持可读尺寸，通过布局节省空间 |
| 主要输入控件 | 按当前组件分别定义 | 以约 32px 高度对齐，保留完整点击范围 |

实施要求：

- 新增具有明确用途的设置布局变量，避免全局修改 `--s-*` 影响所有组件。
- 保持标题栏、侧边栏、底栏稳定，主要压缩右侧内容区。
- 不用裁切、隐藏溢出或缩小正文来制造“首屏放得下”的效果。
- 分组优先使用间距和现有分隔线；背景层数的收敛放在 P1，不混入本次布局提交。
- 焦点环不能被卡片边缘裁切；选择器长文字可以合理换行。

### 4.2 通用页

目标结构：

```text
通用设置
┌ 偏好设置 ─────────────────────┐
│ 开机自启                开关 │
│ 语言                  选择器 │
│ 大界面                  开关 │
│ 聊天大界面              开关 │
└──────────────────────────────┘
┌ 界面主题 ─────────────────────┐
│ 深色            薄荷         │
│ 蜜桃            薰衣草       │
└──────────────────────────────┘
```

具体任务：

- 删除「偏好」「外观」等与所在分组含义重复的徽标。
- 主题卡片中直接放置 `ThemePicker`，移除同名 `Row`。
- 主题网格利用整张卡片宽度，优先采用两列布局，让英文长名称有足够空间，并允许自然换行。
- 精简自动保存说明；只有真正需要解释的行为才保留说明文字。
- 保留主题选择的 `radiogroup`、名称、选中状态和可见焦点。

验收：720 × 520 默认窗口中，四个偏好控件与四款主题完整可见，无横向滚动；在四种语言下逐一检查。

### 4.3 桌宠页

按使用频率调整内容顺序：

1. 当前角色与切换入口。
2. 桌宠大小、显示、置顶、鼠标跟随等常用控制。
3. 昵称紧凑表单行。
4. 角色包库、点击切换说明、导入及较低频的管理操作。

具体任务：

- 移除「桌宠 + 桌宠徽标」的重复表达。
- 取消昵称独立大卡片，合并到相关设置分组；保留输入框标签和原有保存行为。
- 保持 `PersonaPacks` 的角色选择与包管理共用一份状态；将选择器放在顶部，通过内容插槽放置紧凑控制区，再展示包库。
- 保留导入、卸载、卸载当前角色后的回退，以及不同角色渲染类型对应的控制逻辑。
- 包数量增加时允许包库自然向下滚动，不要求把全部角色包塞进首屏。

验收：默认窗口首屏能够看到并操作当前角色、大小和显示开关；其他控制可以自然滚动到达，无按钮遮挡或控件越界。

### 4.4 快捷键与关于页

- 快捷键页保留一张清晰的设置卡片，移除「热键」分类徽标。
- 录制说明放在输入区附近，避免长说明占据过多顶部空间。
- 保持录制、清除、取消以及全局导航快捷键的现有行为。
- 关于页保留图标、名称、动态版本号、简介和作者链接，减少不提供额外信息的装饰标签。
- 保留外链打开失败提示与键盘焦点状态。

## 5. 第二阶段：统一复杂页面与材质（P1）

### 5.1 组件规则

整理 `BentoCard` 和表单行的使用约定：

- 标题负责说明内容；徽标只在能提供新增信息时使用，例如真实的连接状态或条目数量。
- 描述文字只解释行为、范围或后果，避免重复标题。
- 操作区承载与当前分组直接相关的动作。
- 基础组件支持紧凑内容，避免每个页面再叠一层容器修正间距。
- 加载、空状态、错误、禁用和成功提示具有一致的排版与颜色含义。

### 5.2 页面处理清单

| 页面 | 重点 | 验收关注点 |
| --- | --- | --- |
| AI | 统一服务商卡片、模型选择、连接状态和用量信息层级 | 主操作易于定位，凭据输入、验证结果与错误提示完整 |
| 工具权限 | 统一分组标题、开关行和说明间距 | 权限范围与后果清晰，危险操作保持明确区分 |
| 小组件 | 统一任务、番茄钟、工作日志的入口与容器样式 | 时间选择、弹层和日期控件不被裁切 |
| 记忆 | 统一顶部控制、列表与空状态 | 搜索、编辑、删除和确认流程保持可用 |

复杂列表、编辑器和弹层继续使用适合自身的布局，不强制将每一行包成独立卡片。

### 5.3 材质与主题

- 将层级收敛为窗口底色、导航区、内容卡片和控件凹面。
- 优先保留窗口级模糊，评估是否移除卡片与导航上的重复模糊。
- 普通卡片使用轻阴影；选中和聚焦使用明确的边框或焦点环。
- 选中状态与键盘聚焦状态必须能够区分。
- 分别检查四款主题的正文、次要文字、禁用控件和错误提示可读性。
- 保留减少动态效果的系统偏好支持；悬浮动画不得造成布局抖动。

验收：八个导航页面使用一致的基础控件与层级；深色主题没有大面积灰雾遮罩感，浅色主题文字和边界清楚。

## 6. 第三阶段：原生毛玻璃验证（P2，独立交付）

这一阶段在前两阶段布局验收后开展，先验证效果和成本，再决定是否纳入版本。

1. 核对项目实际使用的 Tauri 版本及其原生窗口效果能力。
2. 在独立提交中，仅对设置窗口验证 macOS Vibrancy。
3. 调整网页背景透明度，避免原生模糊与多层网页模糊叠加。
4. 分别在明亮、深色和高对比桌面背景下检查可读性。
5. 验证拖拽、关闭后重新打开、窗口激活切换、圆角边缘和阴影。
6. 检查系统减少透明度偏好，并为效果不可用的情况提供可读的实色回退。
7. 使用相同场景对比改造前后的空闲、滚动和主题切换表现，记录是否出现明显掉帧或持续资源占用增加。

Windows 原生材质保留为后续独立平台任务。本轮 macOS 验收结果不能代替 Windows 验证。

验收：实际桌面上能观察到期望的原生效果，控件文字始终清楚，窗口交互正常；效果不可用时设置窗口仍可完整使用。

## 11. P0 实施与验证记录（2026-09-21）

### 已落地

- 通用、桌宠、快捷键及关于页应用局部紧凑布局；全局主题材质、模糊与阴影保持基线。
- 通用页四款主题直接铺满两列网格，允许完整文字换行。
- 桌宠选择器移至顶部；控制区与昵称合并。包库保留点击切换行为和同一份管理状态，并增加四种语言的操作提示。
- 关于页保留简介、动态版本和作者联系入口，去除重复标签。
- 导航测试使用真实八项导航。真实角色包卸载确认框下，Ctrl/Command+8 不再切走后台页面；取消后恢复导航。已处理的快捷键事件不再重复触发导航，隐藏弹窗不会阻塞快捷键。
