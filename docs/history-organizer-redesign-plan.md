# 会话历史改版施工方案

> 状态：已实施；执行结果和未验证项见第 8 节。
> 日期：2026-09-26。
> 设计基准：本次对话中已认可的交互示意；舒适密度、显示一行内容预览。
> 主验收窗口：420 × 560 逻辑像素；大窗口：720 × 760。

## 1. 本轮要交付什么

将历史窗口改成便于查找、辨认和打开会话的列表。保留现有历史管理能力，默认界面优先展示内容。

完成时应满足：

- 默认窗口中，以“1 条置顶 + 4 条今天的会话”为首屏验收样本，至少完整显示这 5 条普通会话；标题和内容节选可读。
- 搜索始终可见，项目、来源、日期等条件默认收起；生效条件可以直接看见和撤销。
- 同名会话可通过真实消息节选、项目和时间区分。
- 单击记录或按 Enter 打开对应会话；操作菜单独立响应。
- 离线、只读、运行中、归档、删除和会话身份约束保持有效。

首屏条数是正常状态的验收目标。错误提示、特殊状态、较大系统字体可以增加高度，不以隐藏提示或缩小正文满足数量。

## 3. 界面与交互定稿

### 3.1 默认结构

```text
会话历史                         新会话  ×
搜索会话标题或项目                 筛选
会话       已归档                   46 段
──────────────────────────────────────
置顶
  会话标题                        23:24  …
  一行真实消息节选
  项目简称 · 必要的只读/不可用状态

今天
  会话标题                        22:55  …
  一行真实消息节选
  项目简称

昨天 / 更早
  …
```

- 顶部只保留标题、新会话、关闭历史。关闭历史返回原聊天视图，不关闭整个聊天窗口。
- 初次打开及原生会话变化沿用现有刷新机制。手动“刷新列表”移到筛选面板的次要操作区；加载失败继续就近提供“重试”。
- 状态入口为“会话 / 已归档”。“会话”对应未归档记录；置顶是列表内分组，另在筛选中提供“只看置顶”。
- 记录按现有顺序分为“置顶 / 今天 / 昨天 / 更早”，空分组不渲染。归档视图可以保留置顶排序和标识，不改变置顶数据。
- 行主体是可聚焦按钮；更多操作是同级按钮，禁止嵌套按钮或点击冒泡误打开会话。
- 打开操作继续调用 `onOpen → resumeSession → loadSharedConversation`。只读记录仍可按能力打开查看，不把所有记录都宣称为可继续发送。

### 3.2 列表信息

- **标题**：继续使用 `displayTitle`，保证 `userTitle` 优先。单行截断，完整标题可经焦点/悬停或详情查看。
- **消息节选**：显示最近一条有效的用户或助手文本，压成一行；只截取真实文本，不调用模型生成摘要。
- **项目**：一般目录显示末级名；重名时增加最短必要的父目录。内置轻聊天工作区显示“轻聊天”，旧记录显示“本地记录”。路径比较、查询及打开仍用完整规范化目录，不用显示简称做身份。
- **时间**：今天和昨天的分组内显示时分；更早记录显示月日，跨年显示年份。完整时间通过可访问的辅助信息提供；分组使用本地自然日边界。
- **状态**：只读、运行中、不可用等影响操作的信息必须可见；同一原因不重复显示多个徽标。普通可用记录不附加“正常”标签。
- **信息详情**：更多菜单提供查看详情，展示完整路径、来源和完整时间；精简主列表不导致原有信息无法访问。

### 3.3 搜索和筛选

- 搜索框不再同时出现可见标签、相同占位符和重复说明；保留无障碍名称。
- 本轮搜索仍只覆盖标题和项目，保留现有 180ms 防抖。文案明确为“搜索会话标题或项目”，不暗示消息正文已可搜索。
- 筛选面板包含项目、来源、开始日期、结束日期、只看置顶；日期默认空值。
- 面板内筛选即时生效；收起后，在搜索下方显示可逐个删除的条件标签。条件使用短名称，完整值仍可查看。
- “清除筛选”只清除项目、来源、日期和只看置顶，保留搜索词与当前归档视图；搜索有自己的清除入口。无结果状态提供“清除全部查询条件”，保留归档视图。
- 搜索、筛选和归档视图变化均回到第一页，关闭行菜单，并忽略上一查询迟到的结果。
- 结束日期早于开始日期时就近显示错误，不提交无效查询，不把旧结果冒充为该条件下的新结果。
- 正常窗口使用可折叠内联面板，与已认可示意一致；极短窗口允许筛选内容滚动，搜索和关闭入口保持可达。

### 3.4 更多操作和键盘

- 将大号“会话操作”改为始终可见的 `…`，具备包含会话名称的可访问标签。
- 菜单承载重命名、置顶/取消置顶、归档/恢复、详情、删除。能力开关仍由现有 `capabilities` 决定，不能因换菜单开放原本禁用的操作。
- 同时只打开一个行菜单；靠近底部时向上展开，不被列表的 `overflow` 裁切。
- Esc 按层关闭：确认/编辑或菜单 → 筛选 → 历史。关闭后返回对应触发按钮；菜单中操作不触发整行打开。
- 隐藏的筛选控件不能进入 Tab 循环。修正现有根节点焦点收集逻辑，覆盖隐藏元素和菜单焦点恢复。
- 重命名保留校验和失败提示。删除仍经过现有确认框，保留“同时删除仅由此对话产生的记忆”的勾选及失败语义。
- 历史覆盖聊天标题栏后，保留可用的窗口拖动区域，按钮和输入区域不参与拖动。

### 3.5 分页与异常状态

- 总数放在状态入口右侧；0 或 1 页不渲染底部分页栏。
- 多页使用紧凑页码和前后翻页，继续每页 50 条。分页后只渲染该页记录，分组标题允许在不同页重复。
- 当前页最后一条被归档/删除后，必要时回退至最后一个有效页；不能留在“空白的第二页”。
- 加载保留当前可用列表；首次无数据时显示轻量加载状态。失败保留缓存并提供重试。
- 无历史、筛选无结果、目录离线、单条预览缺失分别处理；一条预览失败不导致整页报错。

## 4. 视觉施工规格

以下数值为首轮实现起点，以真实窗口截图收敛，不改变应用窗口大小来满足验收。

| 项目 | 起点 |
| --- | --- |
| 页面左右内边距 | 16px |
| 标题区 | 约 48px 高，标题 17–18px |
| 搜索区 | 36px 控件，含间距约 48px |
| 状态导航区 | 约 32–36px |
| 普通会话行 | 约 68–72px，特殊状态允许增长 |
| 会话标题 / 节选 / 项目时间 | 14px / 12px / 11–12px |
| 图标 / 常规图标按钮 | 16–18px / 28–32px 点击区；触控时扩大 |
| 分组间距 | 8–12px，弱化分组标签 |

首屏固定样本的高度预算：顶部合计不超过 132px，5 条记录合计不超过 360px，两个分组标签及相关间距合计不超过 44px，其余边界与底部留白不超过 16px，总计不超过 552px。样本后再接昨天、更早记录验证滚动；更多分组或特殊状态不套用 5 条硬指标。

执行原则：

- 定义 `--history-*` 局部变量，避免继续复写通用 `--s-*` 或全局字号。
- 窗口主体使用连续、低饱和度表面；搜索只加轻微底色。撤销每行边框与大面积彩色选中框。
- 标题、节选、元信息形成三级对比；主题强调色仅用于焦点和少量必要状态。
- 四款主题分别适配局部中性色、文字和分隔线，不改变设置、桌宠等窗口的共享主题。
- 列表承担主滚动，顶部固定；焦点环、菜单、最后一条记录均不能被裁切。
- 图标复用现有 Phosphor 与 `AppIcon`，补少量所需图标，不引入另一套图标或组件库。
- 第一版固定采用已认可的舒适密度。原型中的密度和标题质量选项是设计比较工具，不加入产品设置。

## 5. 真实消息预览的数据施工

这一部分与视觉同时属于本轮交付；不能仅将演示界面接上真实标题就宣布完成。

### 5.1 接口和职责

- 保留 `history_catalog_list` 作为有界元数据查询，不在其中遍历所有行读取正文。
- 新增只读批量命令 `history_catalog_previews`：输入目录返回的复合 `keys`，以及需要主动更新的标记；按 key 返回短文本或明确的无预览状态。
- 每批最多 12 个 key；主进程全局同时读取至多 2 个原生会话，不是每批各开 2 个。渲染端优先请求可见行，最多预读下方 2 行。
- 待处理队列最多 12 个去重 key；新可见行优先，淘汰已离开当前查询的排队任务。快速滚动不累积批次；在途读取若不能立即取消，受单条读取预算限制，结果还必须经过代次检查。
- 每批总等待预算 10 秒，超时项目独立返回暂不可用；不让一个慢条目拖住整页的查询与操作。工作包 0 要验证超时、取消与响应体限制确实在当前读取链路生效，再进入预览实现。
- 返回结构区分 `ready / empty / unavailable`；`ready` 含文本、角色、原消息时间和 `localOnly` 标记，本地产品回复仍能区分来源。暂定文本上限 160 个 Unicode 字符，显示层再按宽度截断。
- 后端从目录重新解析身份，校验调用窗口、来源命名空间、已删除状态及可读取条件。不得接受任意目录和裸 session ID 组合代替目录身份。
- 从 `history_catalog_load` 抽取可复用的正文读取/文本提取部分，复用原生文本解析和 `catalog_local::combine_messages` 的身份匹配规则。预览不执行打开会话、选择 Agent、修改所有权或创建会话等动作。
- 原生正文继续走现有授权 API；legacy 读取既有本地记录。旧版兼容文本的回退仍需先满足当前的原生内容空白验证规则。

### 5.2 提取、缺失和缓存规则

- 只提取用户/助手的可展示文本。排除系统内容、推理内容、工具事件、工具输出、附件二进制和空白片段；内容以纯文本渲染。
- 合并同一消息的有效文本片段后再选取最近一条，统一空白并做 Unicode 安全截断。
- 新接口不写入 `CatalogEntry`，不修改 `history.json` 或原生数据库；预览只采用有界内存缓存，不新增正文持久化。
- 主进程维护一份有界预览缓存，首版最多 200 项，键和文本总计不超过 512 KiB，30 秒过期；按最近使用淘汰。前端只维护当前列表的展示结果和请求代次，不叠加独立的长期缓存。
- 缓存键包含完整身份与源更新时间。成功的空结果也缓存；暂时失败按 5 秒短退避处理，不能永久记为无内容。
- **本地消息保存必须显式失效对应 key**：当前 `history_save_local_messages` 不一定改变 `CatalogEntry.updated`，仅按时间戳缓存会显示旧节选。
- native 内容更新、成功删除、数据命名空间变化也要失效。缺少具体 key 的现有变更通知按当前可见集合合并刷新，避免每个 token 都拉取全量正文。
- 删除时立即清除展示和缓存；在途响应返回前重新检查记录和请求代次，旧响应不能重新显示已删文本或写回缓存。
- 缺少真实节选时保留标题、项目、时间；必要时用“暂无可预览内容”或“内容暂不可用”说明。不得填入示例内容。

### 5.3 必须先验证的性能点

当前 snapshot 读取完整原生消息，并没有已验证的“只取末条”接口。限制并发不能消除单个超长会话的开销。

施工前半段先用长会话样本确认所固定 OpenCode 版本的实际接口。存在可验证的有界尾部读取时优先使用；否则为预览单独设置请求超时和响应体上限，首轮以每条 5 秒、8 MiB 为预算，读取过程中限制响应量，不能先完整下载再截断。超限返回无预览降级，不阻塞列表，也不改变正式打开会话的读取行为。记录首屏请求数、单次响应量和滚动时新增请求数，再据实调整预算，不把“文本只返回 160 字符”当作读取成本已受限。

本轮不做：全文检索、批量自动重命名、模型摘要生成、原生数据库迁移。后续若增加自动标题，应同步查询语义，并始终尊重用户标题。

- 第 1–2 包可先形成可体验的界面；第 3 包完成前标记为“预览未接通”，不作为最终交付。
- 按工作包分别提交和验收。实现阶段先核对工作区已有修改，不覆盖其他任务的改动。本轮方案不要求升版、打包或发布。

## 7. 验收清单
