# Desktop interaction script (Computer Use)

All interactions target returned windows of the compiled QA executable only. First run `bun scripts/worklog-qa/run.js status` and record owned PID/paths. Use `sky.list_windows()`, filter exact returned app executable plus `YUME Worklog QA ...` title, require one match. Window titles may change at runtime: if so inspect returned QA executable windows, never select a production YUME window. Import @oai/sky in node_repl. Do not automate terminals or use shell commands in a dialog.

For each step: observe screenshot/accessibility; stop to inspect; perform exactly one input; refresh immediately. Focus an observed editable field, refresh to verify focus, then type in a separate cell. Never reuse indexes/coordinates after a state change.

1. Open the QA settings window through its pet menu. Configure only loopback fixture URL, model-a, synthetic-worklog-qa. Record the generated QA provider ID for credential cleanup. Navigate to 工作记录. Capture empty 事项, 日报, 周报, 报告任务, including all relevant scroll positions.
2. In 事项 choose 添加事项. Add 合成测试项目 / 2026-09-07 / 完成测试项目界面核对。 / done. Save, capture readback, then add 2026-09-08 second synthetic item. Exercise project/date filters. Edit one item, capture before/after. If revision conflict can be induced through a supported second QA window, verify 加载最新版本 keeps unsaved draft until explicitly chosen.
3. Set fixture nextTool worklog_record from outside desktop using the loopback control endpoint. In real QA chat send explicit Chinese record request with matching source text/date. Capture tool receipt and work center persisted item. Send ordinary chat with nextTool null; verify zero new records. Test a quoted imperative as untrusted material only after bridge fixture worker confirms scenario contract.
4. Generate daily report using real worklog controls. Set fixture report to exactly reflect synthetic source. Capture queued/running then archived daily report, date/source metadata and 来源 details. Generate weekly report over synthetic dates, confirm no unsupported plans and record uncovered dates.
5. Edit report body with distinct 人工修订保留 marker, save. Update source item, verify stale marker. Regenerate, inspect 版本 dropdown and candidate. Verify current manual version remains until 采用此版本. Capture all version/source expanded states.
6. Create weekly schedule, capture concrete next date/timezone and enabled state. Stop through QA tray exit; run status/stop for remaining owned descendants; relaunch SAME owned roots and fixture. Verify entries/reports/schedule persist. For missed-week recovery use only an approved stopped-app synthetic DB fixture, never change OS clock or production DB; record fixture adjustment and newest-only execution results separately.
7. Configure provider unauthorized or error and generate. Capture visible failure/retry status, set success, retry, verify exactly one report archive. Configure delayMs 15000, start generation, cancel/pause through UI, wait for fixture response, verify cancelled run cannot publish. Capture pending/cancelled/failure controls and final readback.
8. Copy report, inspect synthetic clipboard using an approved clipboard read only. Export Markdown and TXT through the real buttons, which create a new file in native Downloads without a Save dialog. Capture the export receipt (fileName/exportedAt), resolve only that exact newly created filename under trusted Downloads, and read bytes through file tools. Compare exact report text, UTF-8 Chinese and date/name. Record the two owned export paths for final cleanup; copy synthetic export bytes into evidence if needed. Verify duplicate filenames never overwrite an existing file.
9. Exercise source/report delete confirmation with both relationship choices using synthetic duplicates. Capture inline confirmation, cancel once and confirm preservation. Delete only task-created synthetic content under authorized QA scope. Verify undo and related report warnings.
10. Capture final complete surface inventory after last source edit: all four tabs empty/filled; edit/conflict; report metadata/version/source/stale; schedule enabled/paused; running/failed/cancelled; export receipts/delete modals; light/dark theme if supported; narrow/standard viewport only if native app permits resize. UI is fixed 720x520, so never claim untested resize behavior.

Evidence for every capture: sequence ID, exact build SHA256, source fingerprint, timestamp, returned QA window identity/title, action, observed result, screenshot path. Save screenshot data only for durable reviewer evidence; native screenshot already displays and should not be re-emitted for inspection. Keep source text synthetic. Send full fresh image set to independent visual/CJK and functional/design reviewers, not a selected sample. Report gaps explicitly.

Final cleanup: remove synthetic provider through QA settings, exit QA, run stop if necessary, stop exact provider process, verify recorded ports/windows absent. Keep exported report and readback evidence. Delete only recorded QA runtime roots after required persistence checks; log key cleanup and retained artifacts. No production app/credentials/history touched.
